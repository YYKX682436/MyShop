# MyShop 货源 P4 本地验收记录

验收日期：2026-11-20。范围是本地代码、独立 PostgreSQL、模拟支付与模拟供应商；本阶段未部署、未修改生产环境，也未对真实供货站执行采购、转账、退款、申诉、作废或生成 CDKEY。

## 验收结论和阻塞项

**P4-R1：本地 PASS；P4 本地综合验收：PASS；正式上线验收：NOT YET。** 本结论针对源码、隔离 PostgreSQL、模拟支付与模拟供应商；不代表真实易支付交易、真实供应商写接口或公网回调已经验收。此后版本移除了全局采购开关，采购受货源账号启用状态约束；转账和 CDKEY 创建开关仍独立管理。

P4 的易支付事务阻塞已按下述三阶段修复。P1～P3 的采购、卡券、退款与售后实现继续复用原架构；本轮真实供应商及支付写接口均未调用。

本次发现并修复的另外三处问题：

1. 卡券作废处理中，采购完成查询可能在上游作废结果回来前发货。现在同一订单锁内检查未完成的作废操作，结果未知也继续暂停交付。
2. 已关闭或过期订单的支付链接即使经过可信确认也可能被直接拒绝。现在供应商和本地商品均保存独立的迟到付款事件，并在后台订单详情提示人工处理，不恢复订单、不重新采购；一旦存在该事件，隐藏其他付款载体、禁止重新付款，并在采购认领处阻断自动采购。货源账号停用后，尚未过期的历史链接付款仍保留为已付款，采购认领会阻止新的供应商请求。
3. 支付回调原先在等待订单锁前加载了支付尝试实体，锁获得后可能沿用旧状态。现在先读取订单 ID，再按订单、支付尝试顺序加锁并读取最新状态。

P4 初版曾增加 `SUPPLIER_PURCHASE_ENABLED` 全局门禁。后续按正式操作流程移除了该门禁以及 Compose 透传；上架、库存可售、付款和自动采购均依据具体货源账号启用状态及原有库存、价格、规格校验。独立实现中的采购认领仍由数据库确认账号启用状态。

## P4-R1 支付事务与恢复

修复前：直接下单与重付在订单事务内调用 `PaymentProvider.create()`；API 模式可能在持有订单锁时访问网关，支付尝试在返回后才写入，数据库回滚或响应丢失可能产生无法追踪的交易。历史回调对于已关闭的本地订单也可能拒收，人工标记付款后收到真实回执时可能漏记。

修复后：

1. 直接下单在同一短事务内保存订单、订单项、库存预留、供应商意图及支付意图；重付在订单锁内完成所有权验证并提交支付意图。意图保存唯一商户单号、渠道、金额、提供商配置、商品名称、IP、设备及回调/返回地址快照。意图事务未成功提交时不会调用网关。
2. 已提交的 `INTENT` 通过订单锁和支付尝试锁原子认领为 `SUBMITTING`；事务提交后才调用网关，外部调用期间没有活动数据库事务或订单行锁。站点根地址及 `submit.php` 保留浏览器表单；`mapi.php` 和 `pay/apisubmit` 保留 API 创建，原签名和支付动作格式不变。
3. 网关返回后再次短事务锁定最新订单和支付尝试，核对商户单号、金额、渠道与配置快照，再保存载体和返回单号。回调抢先付款、订单过期或退款时不降低付款状态、不重新开放订单、不返回可付款载体。创建响应单号与已确认回调单号冲突时分别保留并转人工核实。

V52 为付款状态新增独立 `creation_status`：`INTENT`（已持久化待发送）、`SUBMITTING`（已认领）、`READY`（载体已保存）、`REJECTED`（确定尚未发送时被阻止）和 `UNKNOWN`（发送或结果保存不确定）。保留原 `PENDING/PAID/FAILED/CLOSED` 付款状态。历史载体默认为 `READY`；`next_action` 允许为空，读取时不再把空值解析为有效动作。部分唯一索引和订单行锁约束未决意图。生产 schema 合约同步至 V52。

- 已提交而尚未认领的 `INTENT` 可以通过同一订单的重付入口继续发送原交易号；已认领或 `UNKNOWN` 不自动重发，也不允许普通重付新建交易。`SUBMITTING` 超过两分钟后在访问时标为 `UNKNOWN`；如果原请求随后返回，仍可按最新状态安全保存结果。
- 超时、无效响应、数据库结果提交失败以及进程被杀后，保留原始交易号。可以查询原交易是否已支付，但查不到不代表交易不存在，易支付查询协议也不能保证恢复原二维码或链接；此类情况需联系网关人工核实，不能自行伪造成功或新建第二笔。
- 支付创建暂未取得载体时，下单响应仍包含已提交的订单和 `creation_status`，`next_action` 为空或因全局非空序列化而省略；前端转到订单页显示创建中或待核实，而不是让顾客重新购买。回调先于响应时只显示已付款状态。订单页以服务器结果清除旧浏览器缓存载体。
- 签名正确但暂时无法通过网关查询确认的通知先保存为 `LATE_PAID_UNVERIFIED`，隐藏付款载体并保留供应商重试；之后查询确认时更新同一事件，再按订单当前状态处理。旧链接迟到付款、人工标记付款后的首次真实回执以及不同尝试的重复到账均保存为独立事件；不重复发货、自动退款或重启供应商采购。若签名通知的网关单号与已保存单号冲突，仅保存为**待核实的冲突证据**，不将其宣称为已确认到账。事件去重同时绑定提供商、商户交易号及提供商事件号；历史事件继续识别。后台订单详情显示支付尝试、单号和事件，并允许管理员留下可追踪的人工核实记录；记录不会自动改变付款、退款或采购状态。
- MyShop 关闭支付尝试不等于网关撤销旧链接，管理员仍须与网关核对实际收款及处理方式；如果网关对多笔资金复用完全相同的商户号与网关交易号，现有协议无法独立区分这些资金，必须依靠网关账单人工对账。

独立 PostgreSQL 测试通过延迟约束触发器模拟意图提交和结果提交失败；以真实 PostgreSQL 行锁及两个 Java 子进程，分别在模拟网关收到请求后、网关响应后但结果事务等待锁时强制杀死进程。恢复时旧尝试保持 `SUBMITTING/UNKNOWN`，均无第二次网关请求。另使用数据库门闩同时阻塞两笔首次下单，在唯一约束竞争后验证只有一个订单和一次创建。

## 转账和 CDKEY 安全边界

- 两项操作先保存独立意图及操作者、账户快照和参数；转账同时生成固定外部单号。短事务内锁定账户并只允许一次认领，之后才发请求。认领后的崩溃、超时、无效响应和结果保存失败均不重发；逾时会标记 `UNKNOWN`。
- 同一账户存在未处理的同类意图或未知操作时，服务端阻止新操作。未认领意图可取消；未知操作必须明确记录人工处理并接受风险后才允许新的独立操作，记录本身不改写为成功。余额变化不作为成功证明。
- 转账仅 `SUPER_ADMIN`，执行前检查账号、余额、正数金额和单次上限；交易密码只参与本次请求，不存入操作参数、响应或审计详情。
- CDKEY 仅管理员可操作及读取；结果在一个事务中加密保存且不进入 `card_keys`。数量、重复码、前缀、长度、短链接和返回格式异常均不能判定成功。展示面额不当作成本；`safePrice` 按单价发送，风险上限按安全单价、兑换数量、发货倍数及生成张数计算。
- CDKEY 文档没有 SKU 参数，因此目前只开放单规格商品；不限制 `safePrice=0` 会失去上游单价保护，本实现要求正数。默认单次转账上限 100、最多 20 张 CDKEY、风险上限 100；均可配置。
- 配置项：`SUPPLIER_TRANSFER_ENABLED=false`、`SUPPLIER_CDKEY_ENABLED=false`，以及 `SUPPLIER_TRANSFER_MAX_AMOUNT`、`SUPPLIER_CDKEY_MAX_COUNT`、`SUPPLIER_CDKEY_MAX_EXPOSURE`。这些值只是本地源码与示例配置，未更改生产。

## 充值字段与规格

文本、数字、单选、多行输入使用现有购买表单，后端验证真实选项值并保存下单快照。级联解析保留父子关系、扩展选项和上游原始值，但 Apifox 仅定义 `attach.value` 为字符串，未说明父子和扩展字段如何编码；因此级联仍禁售。图片字段没有 URL、Base64 或其他提交方式的可靠约定，也仍禁售。复杂正则不在服务端安全子集内时继续禁售，防止正则回溯风险。模板变更会阻止旧采购意图提交，历史订单快照不随之改变。

模拟测试覆盖单规格、多规格和多单规格，以及购买数量、`multiple`、实际数量、成本与总 `safePrice`。真实站点只读样本为单规格且倍数为 1；多规格、多单规格、倍数大于 1 的真实扣费和交付仍未验证。

## 测试与边界

- 独立 PostgreSQL 16：供应商采购、售后及新操作的并发、响应丢失、崩溃恢复、回调重放、订单与售后竞争、超时、账户停用与密钥更换、模板变更和支付迟到回调；CDKEY 结果保存使用 PostgreSQL 延迟约束触发器模拟提交失败。
- 注册用户模拟：商品导入和同步、后台定价、直充字段、余额付款、采购、无卡券交付、申请售后、上游退款、单独执行本地余额退款；验证供应商成本与顾客金额分别记录。
- 游客模拟：商品导入和定价、模拟在线支付、卡券采购与查询、会话隔离和导出、上游卡券作废，以及游客不能使用注册用户退款路径。当前系统不提供游客自助售后或余额退款，必须人工处理。
- 干净库从 V1 迁移到 V52，V51 历史支付载体升级后保持不变；历史版本升级、供应商目录、多账号隔离、本地卡密/人工交付、余额与会员价格等分别在独立 PostgreSQL 中验证。生产 schema 合约与源码迁移版本一致。
- 前端构建、TypeScript、针对性 ESLint、前端逻辑测试及桌面/390px 浏览器模拟覆盖货源管理、危险操作确认、CDKEY 结果、购买表单、订单进度和售后。浏览器测试均拦截模拟接口。
- 供应商采购完成当前不独立发送交付邮件；重复回调不会重复发货，但本次没有证明真实邮件通知。真实支付、真实回调、真实退款、申诉、作废、转账、CDKEY 和直充仍未验收。
