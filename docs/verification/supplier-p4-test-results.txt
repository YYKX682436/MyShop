付款关键证据：
- 同一幂等键的两个首次 INSERT 使用 PostgreSQL advisory lock 门闩同时到达数据库；最终只有一个订单、一个意图和一次网关调用。
- 模拟 Provider 检查调用时无活动事务；网关延迟期间 PostgreSQL 订单行可 NOWAIT 加锁，另一调用可返回创建中。
- 延迟约束触发器分别让意图事务提交失败及网关响应后的结果事务提交失败：前者网关调用为零，后者 UNKNOWN 且不再次提交。
- 在模拟 HTTP 网关收到请求后强制结束独立 Java 进程；以及网关响应已发出、结果事务被 PostgreSQL 订单行锁阻塞后结束进程；重启侧均只转 UNKNOWN、不重发。
- 未认领意图沿用已提交的交易号、设备及渠道配置快照；已认领崩溃、超时、查无交易及不完整载体均不新建付款。
- 回调早于创建响应、人工标付后真实回执、查询成功后重复回调、过期与库存释放、旧链接先后到账、两个商户复用网关事件号、网关单号冲突和签名通知待查询均有 PostgreSQL 回归。
- 待查询的签名通知先持久化，阻止新付款；查询恢复后更新同一事件，完成一次交付。

实施过程中的失败及处理（均已在上面的最终结果中复跑）：
- 初次测试编译因查询事务服务签名变化出现 4 个测试编译错误；更新旧测试后通过。
- 首轮 49 项定向单测中 12 项失败、15 项报错，原因是旧测试未装配事务模板及仍使用旧支付入口；调整测试装配后只剩 1 项旧调用断言，修正后通过。
- 曾复用已执行过的临时测试库导致 PostgreSQL 发货套件 10 项重复数据错误；后续每套使用新建独立库，通过。
- PostgreSQL 行锁测试一次 NOWAIT 与第二个正常短事务瞬时争锁；等待并发调用结束后再检测网络期间的锁，复跑通过。另有一项旧渠道快照单测夹具与订单渠道不一致，修正夹具后通过。
- 核心稳定性首次发现过期异常在嵌套事务中标记回滚，导致库存释放无法提交；已修复事务异常规则并通过复测。
- 供应商旧回归预期迟到付款后另一笔付款仍自动完成订单；改为记录两笔并转人工处理，更新断言后通过。
- 前端逻辑测试最初有 2 项仍要求无支付动作时停留商品页的旧断言；按已提交订单的恢复行为修正后通过。
- 供应商浏览器脚本首次因本地预览未启动出现连接拒绝；启动仅监听 loopback 的模拟预览后通过。
- 增加签名通知待查询记录后，供应商测试原先要求查询金额不一致时不留事件；实际安全行为是先保存未验证事件、等待后续确认。已更新该断言并复跑。
