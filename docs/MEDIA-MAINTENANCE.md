# 公开资源维护

查看引用使用数据库中的当前引用，不再扫描全部表或持有媒体全局排他锁。删除前显示当前受影响的商品、头像、主分站图标和公告字段；确认后允许删除正在使用的资源。删除在事务中锁目标资产及受影响的业务行，清空直接字段，对商品详情和公告用 Markdown AST 移除对应媒体节点并保留其他内容。正文为空时公告使用明确占位，以满足原有正文约束。订单历史快照及日志不参与当前引用清理。

业务保存按固定顺序锁定所引用的有效资产并更新引用；删除锁定目标资产后按固定顺序处理引用行。旧编辑表单不能重新挂回已删除资源，删除不会反向锁定正文中的其他资源，也不会让无关订单写入等待全库媒体锁。头像独立归属账号，更换或删除头像不会删除商品图片。

数据库提交删除后清理实际文件和派生版本。若物理清理失败，资源已处于删除状态，界面显示失败并允许再次清理；不能将已提交业务变更描述为回滚。视频取消也保留清理状态，处理中的任务退出后清理其临时文件，服务重启时会重试待清理的取消会话。已发出的浏览器或代理缓存不能撤回。

V63 新增资产和引用表；新 API 在启动时、独立短事务中登记旧文件并回填明确业务字段，完成后写入切换标记。V64 只有在标记存在时才移除旧媒体全局保护触发器，不修改订单快照约束或其他数据库规则。生产部署先停止该 Compose 项目中的旧 API 并确认无残留实例，再由新 API 自行执行分阶段迁移。schema 检查同时核对切换标记及旧媒体触发器已移除；迁移发生变化后的失败遵循现有正向恢复流程。
