# 图片资源维护

- 商品封面和后台缩略图中的本地顶层 UUID/SHA-256 图片使用受控的 Next.js 图片入口。GIF 和外部 URL 保持原格式；优化入口只读取固定的公开后端路径。
- 删除需要管理员确认。操作会清空可识别的商品封面、网站 Logo、图标、分站 Logo 和联系方式二维码；无法安全改写的 Markdown 和历史数据保留。订单封面快照不变，但新返回的订单数据对已删除的本地图片使用占位图。
- 检查结果会列出涉及的表及记录数。站外引用无法识别，浏览器、图片优化器和上游反向代理中已有的缓存副本无法撤回。Markdown 中的本地受管图片通过不缓存的受控入口读取，以便新页面在文件删除后显示占位图。
- 管理员可逐张优化不超过 10 MB、400 万像素及 2560 像素边长、没有动画或复杂颜色配置的 PNG/JPEG。合适的不透明 PNG 可转为高质量 JPEG；转换后只有尺寸明显减小且误差检查通过才会使用。透明图、二维码和高对比图优先保留原格式。结果显示切换的商品和保留的历史引用，原文件不会自动删除。
- 二维码上传入口显式保留原始文件；普通上传也会尝试识别二维码及高对比图案并保留。新文件以实际输出字节的 SHA-256 命名，同一处理结果可复用，旧 UUID 文件不会自动全库去重。
- V58 保留 V27 订单快照不可修改约束。媒体写入保护拒绝新增已删除资源的引用，允许未改变的历史字段与其他合法字段一起保存。删除先在独占锁内提交商品字段变更及标记，再清理名称和文件；清理失败会返回错误，保留的文件可在资源管理中重试。
- 删除标记是防止悬空引用的持久状态，不应当作普通临时文件清理。重新上传相同内容时校验 SHA-256 并清除标记。后续迁移新增业务表时应安装 `myshop_media_guard` 触发器，否则资源维护会拒绝执行。
