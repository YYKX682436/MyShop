# 图片资源维护

- 商品封面中的本地、顶层 UUID/SHA-256 图片通过 Next.js 按显示尺寸生成缓存；GIF、非标准路径和外部图片仍使用原地址。优化器只允许 `/image-source/*`，该入口只读取固定的后端公开图片路径，不接收外部目标地址。原始公开 URL 不变。
- 资源管理中的删除和优化需要管理员主动选择并查看引用状态。删除会扫描业务数据；无法解析的转义或未受保护的数据库表会阻止操作。站外引用无法识别，浏览器及优化器中已有的缓存副本也不能撤回。
- 旧图优化仅处理不超过 10 MB、400 万像素、2560 像素边长的静态 PNG；有动画、颜色配置或方向信息的图片会跳过。处理结果必须更小且逐像素一致。仅可确认的商品封面引用会替换，原图保留；其他引用或并发变更会阻止替换。没有部署时自动处理或批量处理。
- V56 的删除标记和数据库写入触发器保护“检查后有其他事务写入旧 URL”的情况。删除前会提交标记，再删除公开文件；相同内容重新上传时验证 SHA-256 并清除标记。标记是防止悬空引用的持久状态，不应按普通临时文件清理。后续迁移新增业务表时应为其安装 `myshop_media_guard` 触发器，否则资源维护会拒绝执行。
- 数据库和文件系统不是同一事务。异常中断可能留下无引用文件或删除标记；不要直接移除标记来绕过保护。可重新上传相同内容或重新检查该资源后再操作。
